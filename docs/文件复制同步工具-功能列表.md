# 文件复制与同步工具功能列表

## 1. 产品定位

开发一款面向 Windows 桌面用户的文件复制与同步工具，用于在本地磁盘、移动存储设备、局域网共享目录等位置之间，安全、快速、可追踪地完成文件复制、备份和目录同步。

产品应优先保证数据安全和任务结果可验证，任何覆盖、删除或冲突处理都应明确告知用户，并支持预览或恢复。

## 2. 目标用户与使用场景

### 2.1 目标用户

- 需要频繁复制大量文件的普通用户
- 需要在电脑、移动硬盘和 NAS 之间同步资料的用户
- 需要定期备份项目、照片、文档等内容的用户
- 需要查看复制失败原因和重试任务的专业用户

### 2.2 典型场景

- 将一个目录完整复制到另一个目录
- 将源目录中的新增或修改文件增量同步到目标目录
- 让两个目录保持内容一致
- 定时将工作目录备份到移动硬盘或网络共享目录
- 复制大文件或大量小文件，并查看实时进度、速度和剩余时间
- 在执行覆盖或删除前预览实际变更
- 任务中断后继续执行，而不是重新开始

## 3. 功能优先级说明

- **P0：核心功能**，首个可用版本必须具备
- **P1：重要增强**，核心版本稳定后优先开发
- **P2：高级功能**，根据实际使用反馈逐步加入

## 4. 功能列表

### 4.1 复制任务（P0）

- 选择一个或多个源文件、源目录
- 选择目标目录
- 支持文件复制、目录复制和目录结构递归复制
- 支持拖拽添加文件或目录
- 支持同名文件处理：覆盖、跳过、重命名、询问
- 支持仅复制新增文件
- 支持仅复制新增和已修改文件
- 支持保留文件时间、属性和目录结构
- 支持长路径、中文路径、空格及常见特殊字符
- 支持大文件和大量小文件复制
- 支持暂停、继续和取消任务
- 支持中断后重新执行未完成内容
- 支持失败文件单独重试

### 4.2 目录同步（P0）

- **单向同步**：源目录变更同步到目标目录
- **镜像同步**：目标目录最终与源目录保持一致
- **累加同步**：只复制新增和修改文件，源端删除不影响目标端历史文件
- 执行前扫描源目录和目标目录
- 展示待新增、待更新、待删除和冲突文件
- 支持按文件大小和修改时间判断变化
- 支持可选的文件内容校验判断变化
- 支持同步空目录
- 支持目标目录多余文件的处理策略：保留、删除、移入回收区/隔离区

以下模式在核心同步稳定后作为 P1 开发：

- **双向同步**：两边的新增、修改和删除相互传播
- **移动同步**：把源目录文件移动到目标目录，成功后清理源文件
- **更新同步**：只保留当前批次新增或更新的文件，清理任务以前复制的旧文件
- 双向同步时识别双方均已修改的冲突文件
- 冲突处理方式：保留源文件、保留目标文件、保留两份、逐项确认
- 双向同步应保存两端上次同步状态，不能只通过当前文件时间猜测删除和冲突
- 移动同步必须在目标文件写入并校验成功后才能删除源文件

> 镜像同步、双向同步、移动同步和更新同步都可能删除数据，必须默认先预览，并对删除操作进行明确提示。

### 4.3 任务预览与执行确认（P0）

- 执行前显示源路径、目标路径和任务模式
- 显示预计新增、覆盖、跳过、删除和冲突数量
- 显示预计复制数据总量
- 支持按变更类型筛选预览结果
- 支持展开查看具体文件清单
- 支持从本次任务中排除指定文件
- 对覆盖、删除、大批量变更等高风险操作进行二次确认
- 检测源目录与目标目录相同、互相包含等危险路径关系
- 检测目标磁盘可用空间是否足够

### 4.4 过滤规则（P0）

- 按文件名或通配符包含/排除文件
- 按扩展名包含/排除文件
- 按目录名称排除目录
- 按文件大小范围过滤
- 按修改时间范围过滤
- 支持隐藏文件、系统文件的包含策略
- 支持符号链接/目录联接点的处理策略
- 提供常见排除项示例，如临时文件、缓存目录和回收站目录
- 支持保存过滤规则并在任务中复用

### 4.5 进度与状态展示（P0）

- 显示任务总体进度和当前文件进度
- 显示已完成、待处理、跳过、失败文件数量
- 显示已复制数据量、总数据量
- 显示当前速度、平均速度和预计剩余时间
- 显示当前正在处理的文件和路径
- 显示任务状态：等待、扫描、运行、暂停、完成、失败、已取消
- 支持最小化到系统托盘后继续执行
- 任务完成、失败或需要处理冲突时发送桌面通知

### 4.6 错误处理与恢复（P0）

- 对单个文件失败进行记录，不因非关键错误终止整个任务
- 提供错误原因，如权限不足、文件占用、空间不足、路径不存在、网络断开
- 支持自动重试，并可配置重试次数和间隔
- 支持任务结束后集中重试失败项
- 网络或移动存储短暂断开后支持等待并继续
- 取消任务时保证当前写入文件处于可识别状态，避免把不完整文件当作成功文件
- 对临时文件进行清理或在下次启动时提示恢复
- 保存任务运行状态，应用异常退出后可识别未完成任务

### 4.7 完成校验（P0）

- 默认使用文件大小和修改时间进行快速校验
- 可选使用哈希值进行严格校验
- 支持仅校验、不复制
- 在任务结果中展示校验成功和失败数量
- 校验失败的文件可重新复制
- 任务完成后生成明确结论：成功、部分成功、失败或已取消

### 4.8 任务管理（P1）

- 保存常用复制或同步任务
- 编辑、复制、重命名和删除任务配置
- 一键重新运行历史任务
- 支持任务队列和并行任务数量限制
- 支持调整任务顺序和优先级
- 支持任务分组
- 支持配置任务依赖关系和前置任务
- 支持配置任务启动前和完成后的动作
- 支持任务执行前后运行受控的外部命令
- 支持导入、导出任务配置
- 支持一个任务包含多个源目录或源文件
- 支持为任务添加名称、说明和标签
- 记录任务最近运行时间和结果

### 4.9 计划任务与自动同步（P1）

- 支持手动、每天、每周、每月定时运行
- 支持固定时间和间隔运行
- 支持应用启动后运行或用户登录后运行
- 支持检测移动硬盘接入后运行指定任务
- 支持源目录或目标目录可用时自动运行
- 支持文件变化后延迟触发同步，避免频繁执行
- 明确“实时同步”的语义：文件变化负责触发，执行时仍进行完整的差异扫描
- 支持错过计划后的补跑策略
- 支持运行前确认或完全自动运行
- 自动任务执行删除、覆盖等操作时使用独立的安全策略
- P2 支持 Windows Service 后台运行，在用户未登录时执行计划任务

### 4.10 历史记录与日志（P1）

- 保存每次任务的开始时间、结束时间、耗时和结果
- 记录新增、覆盖、跳过、删除、冲突和失败文件
- 支持按任务、时间和结果查询历史记录
- 支持查看错误详情和失败文件列表
- 支持导出日志为文本、CSV 或 JSON
- 支持打开日志文件所在位置
- 支持配置日志保存期限和自动清理策略
- 日志避免记录凭据等敏感信息

### 4.11 数据安全与版本保留（P1）

- 删除文件时优先移入系统回收站或任务隔离区
- 覆盖文件前可选保存旧版本
- 支持设置旧版本保留数量或保留天数
- 支持从任务历史或隔离区恢复文件
- 支持历史增量备份：首次建立完整基线，后续仅保存新增和修改内容
- 支持按指定执行时间点恢复当时的完整目录结构
- 支持完全备份：每次建立独立子目录并保存源目录完整快照
- 提供选择性恢复，可只恢复指定目录或文件
- 备份数据清理时维护恢复链完整性，禁止留下无法恢复的日志记录
- 支持预演模式，仅展示变化而不执行
- 支持设置单次任务最大删除数量或比例
- 超过安全阈值时阻止自动执行并要求人工确认
- 防止目标路径误选为系统关键目录

### 4.12 性能设置（P1）

- 支持配置并发复制数量
- 支持配置复制缓冲区大小
- 支持复制速度限制
- 支持自动根据磁盘类型和文件数量调整策略
- 针对大量小文件优化扫描和复制效率
- 针对大文件提供稳定进度和断点恢复能力
- 降低后台运行时的 CPU、内存和磁盘占用
- 支持跳过未变化文件，减少无效读写

## 5. 同步模式定义

| 模式 | 数据方向 | 目标目录多余文件 | 冲突风险 | 推荐用途 |
| --- | --- | --- | --- | --- |
| 普通复制 | 源到目标 | 保留 | 低 | 临时复制文件 |
| 增量复制 | 源到目标 | 保留 | 低 | 日常追加备份 |
| 单向同步 | 源到目标 | 按任务记录同步删除，忽略目标端额外变化 | 中 | 更新受任务管理的目标副本 |
| 镜像同步 | 源到目标 | 删除或隔离 | 高 | 生成完全一致的镜像 |
| 累加同步 | 源到目标 | 永久保留 | 低 | 保留源端曾经出现过的文件 |
| 双向同步 | 双向 | 合并 | 高 | 两个工作目录保持一致 |
| 移动同步 | 源到目标 | 保留 | 高 | 将源文件安全归档后清空源端 |
| 更新同步 | 源到目标 | 清理以前复制的旧文件 | 高 | 目标端仅保存最新更新批次 |
| 历史增量备份 | 源到带时间点的版本库 | 按保留策略清理 | 中 | 恢复指定时间点的目录状态 |
| 完全备份 | 源到独立完整快照 | 按保留策略清理 | 低 | 周期性完整备份 |

## 6. FileGee 竞品功能参考

### 6.1 产品定位

FileGee 是一款面向 Windows 的任务式文件同步、自动备份和恢复系统。它把源位置、目标位置、执行方式、过滤规则、触发时间、失败重试和日志保存封装为可重复运行的任务，定位比普通文件复制器更接近完整的备份平台。

截至本次调研，FileGee 官方下载页公布的版本为 **12.1.8**，发布时间为 **2026 年 5 月 13 日**。

### 6.2 已确认的主要能力

- 六种同步模式：单向、双向、镜像、移动、更新和累加同步
- 两种历史备份模式：增量备份和完全备份
- 本机、移动存储、网络共享、FTP/SFTP、MTP、网盘和对象存储之间传输
- 手动、实时、间隔、每日、每周和每月等触发方式
- USB 设备接入触发、任务依赖、命令行启动和任务执行前后命令
- 多任务并行、多线程传输、错误重试、执行进度和逐文件日志
- 历史增量备份恢复、选择性恢复和独立恢复工具
- ZIP 压缩、内容加密、文件名加密、邮件通知和代理设置
- Windows Service 后台运行，以及企业多用户集中管理和私有传输通道

### 6.3 值得借鉴的设计

1. **以任务为产品核心**：用户配置一次后可以手动、定时或被事件反复触发。
2. **严格区分同步与备份**：同步解决目录状态传播，备份解决历史时间点恢复。
3. **同步模式语义明确**：尤其区分单向同步、镜像同步和累加同步对目标端变化的不同处理。
4. **完整的可靠性闭环**：预览、执行、进度、日志、重试、校验和恢复相互衔接。
5. **任务状态持久化**：中止后记录已完成内容，下次运行不重复处理成功文件。
6. **自动化与核心引擎复用**：手动执行、计划任务、实时触发和命令行最终调用同一套任务逻辑。
7. **存储接口抽象**：源端和目标端都通过存储适配器访问，便于增加网络或云端类型。

### 6.4 我们的产品取舍

- 第一阶段不追求覆盖 FileGee 的全部存储协议，先把本地磁盘、移动存储和 Windows 网络共享做稳定。
- 首版重点做好普通复制、单向同步、镜像同步、累加同步、预览、删除保护、失败重试和结果校验。
- 历史增量备份需要独立的版本索引和恢复链设计，不应等同于“只复制变化文件”。
- 双向同步需要可靠的状态数据库和冲突策略，不能只比较文件修改时间。
- 界面重点突出模式后果、待删除文件和最终执行结论，降低传统专业工具的学习成本。
- “热备份”不能只尝试绕过文件占用；数据库等一致性敏感数据应优先采用 VSS 或应用专用备份机制。

## 7. 原始首版范围（已全部完成并扩展）

首版建议只聚焦本地磁盘、移动存储和 Windows 网络共享目录，包含以下能力：

1. 新建普通复制、增量复制、单向同步、镜像同步和累加同步任务。
2. 扫描并预览新增、覆盖、跳过和删除项。
3. 配置基础过滤规则和同名文件处理方式。
4. 执行任务并展示进度、速度、剩余时间和当前文件。
5. 暂停、继续、取消、失败重试和异常恢复。
6. 使用文件大小与修改时间快速校验，可选哈希严格校验。
7. 保存常用任务、运行历史和详细日志。
8. 默认启用删除保护、危险路径检测和磁盘空间检查。

原规划中暂缓的双向同步、移动同步、更新同步、历史增量备份、云盘、远程协议、加密压缩和插件系统已经在 1.0.0 中完成。双向同步使用 SQLite 成功快照判定新增、修改、删除和冲突；历史增量备份维护独立恢复链，不与普通增量复制混用。

## 8. 非功能性要求

### 8.1 安全性

- 未经明确确认，不静默删除或覆盖用户数据
- 所有任务结果可查询、错误可定位
- 配置文件损坏不应影响用户文件
- 凭据必须使用安全存储，不写入普通日志或明文配置

### 8.2 稳定性

- 单个文件失败不导致整个任务异常退出
- 应用重启后能够识别未完成任务
- 磁盘空间不足、设备移除、网络中断等情况应可控处理
- 任务完成状态必须基于实际复制和校验结果

### 8.3 性能

- 扫描和复制过程不阻塞界面操作
- 能处理深层目录、大文件及大量文件
- 后台运行时资源占用可配置
- 进度数据应持续更新但不明显拖慢复制速度

### 8.4 可维护性

- 复制引擎、同步比较、任务调度、日志和界面相互解耦
- 同步策略和存储类型应便于扩展
- 核心复制与同步逻辑应具备自动化测试
- 对覆盖、删除、冲突和异常恢复建立重点测试用例

## 9. 已确定的产品决策

- 1.0 仅支持 Windows x64，核心分层保持可测试性，但不承诺跨平台界面和系统集成。
- 默认变化与完成校验使用大小和时间；高可靠任务可启用 SHA-256，严格同步快照同时保存内容哈希。
- 断点恢复同时覆盖任务级检查点和单个大文件分块续传。
- 镜像、移动、更新和删除传播默认进入 CopyTools 隔离区，超过数量或比例阈值时阻止自动执行。
- 桌面端和服务使用同一应用内调度与任务数据库，不依赖 Windows 任务计划程序。
- 同时提供自包含便携版和安装版；默认数据位于 `%LOCALAPPDATA%\CopyTools`。
- 网络和远程凭据使用 Windows Credential Manager，不写入普通配置和日志。
- 配置备份包含设置、任务、计划、触发器、存储连接元数据、通知配置和同步状态；SQLite 初始化包含向后兼容迁移。
- 移动同步和更新同步保留为明确独立模式，避免用户用组合规则猜测删除语义。
- 历史增量备份采用自研内容版本库与快照索引；清理策略在事务内维护恢复链可用性。
